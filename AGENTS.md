# Research Code Rules

- **Research code must be reusable: expose every model, dataset, representation, and evaluation as an importable, parameterized Python API; keep CLI modules as thin wrappers around those APIs so future studies in this repository can compose them.**
- Read `PROGRESS.md` first for the live pipeline/status, then `CLAUDE.md` for repository history and data layout. Treat `outputs/README.md` as the canonical index of `src/train/` runs and results.
- Treat `MODEL_BENCHMARK_REPORT.md` as the fixed evaluation protocol, `EXECUTION_CHECKPOINTS.md` as the resumable phase/run ledger, and `observations/MULTIMODAL_EVALUATION_RESULTS.md` as the generated-results report. Update the execution ledger after every verified phase and record every saved model or embedding in `outputs/README.md`.
- Preserve provenance for every experiment: explicit seed, input embedding keys, split definition, configuration, checkpoint, metrics, and named output directory. Do not silently overwrite a prior run.

## Central Research Architecture

- The central hypothesis is that independently learned gene and histology vectors can be aligned by same-spot correspondence and then fused into one identifiable spot representation. The primary unsupervised path is `img_emb` (a given frozen 128-d image-BYOL feature) + `gene_emb` (the repository's 128-d gene-BYOL feature) -> two trainable cross-modal heads -> `img_emb_cm` + `gene_emb_cm_img` -> normalized mean/angle bisector. Test whether this representation preserves biological neighborhoods; do not assume that improved pair retrieval proves useful domain structure.
- Image BYOL itself is external to this repository: the source `.h5ad` files already contain `adata.obsm["img_emb"]`. Do not claim that `src/train/` trains image BYOL. `src/train/` is a separate label-assisted metric-learning ablation that maps `img_emb` to `proj_emb` using same/different `ground_truth` cortical-layer pairs.
- Gene BYOL is implemented in `src/gene_encoder/`. `hvg_selection.py` chooses 3,000 joint batch-aware HVGs; `spatial_graph.py` builds within-section spatial KNN graphs (`k=6`); `augmentations.py` and `model.make_view_augmentations()` create a stochastic masked/noisy expression view and a deterministic self-plus-neighbor mean view; `model.py` defines the `3000 -> 512 -> 512 -> 128` `GeneEncoder`, wraps it with `byol-pytorch`, and adds encoder-output variance regularization; `train.py` trains and exports the unaugmented encoder output; `attach_gene_embeddings.py` stores it as `gene_emb`.
- BYOL is non-contrastive and uses no negatives. Its online predictor is trained to match the stop-gradient target projection of the same spot's other view, and the target parameters follow the online branch by EMA (`ema_decay=0.996`). The optimized gene objective is `BYOL loss + variance_weight * variance loss`; the internal BYOL projector/predictor outputs are training-only, while the raw 128-d `GeneEncoder` output is the saved representation.
- Cross-modal alignment is implemented in `src/cross_modal/`, after the independent embeddings have been learned. `model.py` defines separate trainable gene and image heads (`Linear -> LayerNorm -> GELU -> Dropout -> Linear -> L2 normalize`) plus a learned temperature. For a batch, `S_ij = exp(logit_scale) * cosine(gene_i, image_j)`; the diagonal same-spot pairs are positives and every off-diagonal pair is an in-batch negative. `clip_loss()` averages gene-to-image and image-to-gene cross-entropy. Source embedding arrays are fixed; only the two heads and temperature are optimized.
- `src/cross_modal/train.py` runs independently for `gene_emb <-> img_emb` and `gene_emb <-> proj_emb`; these runs do not share heads. They export both sides to an NPZ, and `attach_cross_modal_embeddings.py` maps them to `gene_emb_cm_img`/`img_emb_cm` or `gene_emb_cm_proj`/`proj_emb_cm`. The latter pair is not a fully unsupervised path because `proj_emb` used layer labels upstream.
- `src/multimodal/bisector.py` implements the proposed single spot vector as `normalize(normalize(image) + normalize(gene))`. For unit vectors this is the angular bisector and a normalized mean. It is unique per spot only insofar as the learned pair retains spot-specific information; uniqueness alone does not imply that same-layer spots form clusters or that the representation generalizes to unseen tissue.

## Training And Artifacts

- Gene preparation artifacts are `outputs/gene_encoder/shared_hvgs.json` and `outputs/gene_encoder/spatial_knn_graph.pkl`. Gene training writes `outputs/gene_encoder/checkpoints/<run>/{best,last}.pt`, per-epoch metrics CSV, and `predictions/<run>_embeddings.npz` containing `embeddings`, `barcodes`, `section_ids`, and `split`. Export uses a plain forward pass on unaugmented expression through the best raw encoder.
- Cross-modal training writes `outputs/cross_modal/checkpoints/<run>/{best,last}.pt`, per-epoch loss/retrieval metrics, and `predictions/<run>_embeddings.npz` containing normalized `gene_projected`, `image_projected`, `barcodes`, `section_ids`, `split`, and the source `image_key`. Validation loss selects `best.pt`; retrieval accuracy is a monitoring metric, not the optimization target or a clustering score.
- Keep model checkpoints distinct from `checkpoints/dlpfc.pkl`: model checkpoints store weights/configuration/metrics, while `dlpfc.pkl` stores the full per-section `AnnData` collection and attached per-spot vectors. Embedding attachment must remain a separate explicit operation.
- Current GBSSA study artifacts are indexed in `outputs/README.md`. Gene runs use `outputs/gene_encoder/{checkpoints,metrics,predictions}/gene_byol_gbssa_seed*`; cross-modal ratio runs use `outputs/cross_modal/{checkpoints,metrics,predictions}/gbssa_img_*`; immutable common evaluations use `outputs/evaluation/<run_id>/`. The canonical `checkpoints/dlpfc.pkl` remains untouched; `checkpoints/dlpfc_gbssa_seed0.pkl` is a run-specific copy containing the seed-0 replacement `gene_emb`.

## Pipeline Contracts

- `DlpfcDataset` (`src/datasets/dlpfc.py`) is the shared 12-section DLPFC source. It keeps one `AnnData` per section and stable section order; use `DlpfcDataset.from_checkpoint(Path("checkpoints/dlpfc.pkl"))` for repeated work. The checkpoint is about 5 GB and is git-ignored.
- The current checkpoint embedding contract is 128-d `img_emb`, `proj_emb`, `gene_emb`, `gene_emb_cm_img`/`img_emb_cm`, and `gene_emb_cm_proj`/`proj_emb_cm`. `src/multimodal/` intentionally defaults to the stronger `gene_emb_cm_img` + `img_emb_cm` pair.
- Never merge spots on barcode alone: Visium barcodes repeat across sections. Use `(section_id, barcode)`, and retain the existing write-to-`.tmp` -> reload/validate -> atomic `Path.replace()` pattern for checkpoint mutation.
- One shared gene encoder requires the joint, batch-aware shared-HVG output from `src.gene_encoder.hvg_selection`; per-section HVG flags are not a common feature space. `adata.X` is log1p-normalized, so use the established `seurat` HVG flavor, not `seurat_v3`.
- Gene BYOL needs its encoder-output variance regularizer. Plain BYOL collapsed in this dataset; monitor `embed_std` and do not remove or disable the regularizer without an explicit ablation.
- Image-projector pairs are by `adata.obs["ground_truth"]` cortical layer, never tissue section. `slice_ids` are metadata only; `slice_projector` artifacts are pre-fix historical outputs, not canonical results.

## DLPFC Terminology And Fields

- DLPFC has three repository donor IDs and twelve biological tissue sections: donor 1 = `151507`-`151510`, donor 2 = `151669`-`151672`, donor 3 = `151673`-`151676`. Do not invent `Br*` donor names unless an external verified mapping is supplied.
- Call `151507` and similar biological slides **sections**, not slices. The seven annotation values in `adata.obs["ground_truth"]` are `Layer_1` through `Layer_6` and `WM`; use the exact observed valid labels when deriving a label-count-informed cluster count.
- Per-spot gene expression is `adata.X`, image features are `adata.obsm["img_emb"]`, coordinates are `adata.obsm["spatial"]`, and barcodes are `adata.obs_names`. The keys `"x"` and `"img"` exist only in `DlpfcDataset.__getitem__()` sample dictionaries; `adata["gene"]` and `adata["img"]` are not modality fields.
- Reserve **slice** for the legacy synthetic group in `src/analysis/slice_grouping.py`: a fixed-size random group from one `(section, layer)` pair (current default 20 spots). Legacy `slice_ids` variables in `src/train/` actually store section IDs. Do not propagate that ambiguous naming into new APIs.
- Do not hardcode approximate spots per layer. Read exact counts from each section, retain missing-label handling, and treat `(section_id, barcode)` as the spot identity.

## Evaluation And Benchmarking

- Separate supervised and unsupervised claims. Unsupervised clustering may use labels only after clustering for Hungarian-matched accuracy, ARI, and NMI. Supervised multimodal methods 3 and 4 must reuse `shared_train_test_split` for a fair comparison.
- Evaluate each claim separately. Cross-modal alignment: held-out bidirectional Recall@K, mean reciprocal rank or median rank, FOSCTTM, paired-vs-unpaired cosine gap, and collapse/effective-rank diagnostics. Representation quality: identical frozen linear, k-NN, or nearest-centroid probes with accuracy, balanced accuracy, macro-F1, and per-layer recall. Domain discovery: per-section ARI/NMI and secondary Hungarian accuracy over multiple seeds. Spatial quality: spatial-neighbor label agreement, connectedness, Moran's I/Geary's C, and boundary or marker-gene coherence. Integration: report biological conservation together with section/donor mixing (for example iLISI/BatchKL); batch mixing alone is not success.
- An InfoNCE gain does not establish a clustering gain. Exact-spot InfoNCE makes every other spot a negative, including nearby or same-layer spots, so it can improve one-to-one retrieval while dispersing biologically related spots. Diagnose this tension with similarities and retrieval stratified post hoc by same layer, different layer, spatial neighbor, and distant spot; annotations are diagnostic only and must not enter unsupervised training.
- Test the fusion hypothesis against matched controls: raw gene/PCA, `gene_emb`, `img_emb`, unaligned bisector, each aligned modality alone, aligned bisector, concatenation with the same downstream probe, and shuffled spot-pair InfoNCE. Put all `proj_emb` variants in a separate label-assisted table. Keep dimensions, split manifests, clustering backend, seeds, and downstream model capacity fixed where possible.
- Current `src/multimodal/bisector.py` pools all sections and runs `KMeans(k=7)`, where `k` comes from the known annotation count. Describe this as label-count-informed unsupervised clustering, not fully label-free model selection. The current pooled result (accuracy 32.2%, ARI 0.090, NMI 0.163) is evidence that the existing bisector does not yet recover pooled cortical domains, despite above-chance cross-modal retrieval; do not hide or reinterpret this negative result.
- Current pooled 12-section evaluation is not a final generalization claim. For publishable cross-tissue conclusions, use whole-section or whole-donor holdouts where available and report the split unit.
- Use three named regimes rather than mixing claims: per-slice transductive clustering for direct domain-discovery comparisons; joint-slice training with batch and biology metrics for integration; and leave-one-donor-out (secondary: leave-one-section-out) for inductive generalization. In strict donor holdout, fit HVGs, preprocessing statistics, gene BYOL, InfoNCE, checkpoint selection, and supervised probes on training donors only, then freeze everything for the test donor. If the external image BYOL's training provenance is unknown, call it a fixed external feature extractor rather than claiming end-to-end donor generalization.
- STAIG is the reference benchmark (`STAIG.pdf`): it combines gene expression, spatial KNN graphs, BYOL image features, image-guided graph augmentation, and neighbor contrastive learning; its DLPFC comparison reports per-slice ARI/NMI and alignment-free integration. Do not equate this repository's pooled spot-level accuracy or k-NN diagnostics with STAIG's clustering metrics.
- Compare against STAIG in two fair views: each method's native pipeline and a common-embedding evaluation with identical data, cluster count/backend, refinement policy, seeds, and metrics. Compare per-slice ARI/NMI to STAIG's DLPFC domain-identification results and joint-slice ARI/NMI plus BatchKL/iLISI to its integration results; never compare InfoNCE retrieval or supervised accuracy directly to those values. Useful modern baselines include conST, DeepST, SpaGCN, stLearn, GraphST, MuCoST, STAGATE, and SEDR, but record which methods receive image, gene, and spatial-graph inputs.
- Treat sections, not spots, as biological replicates for clustering comparisons. Report all 12 section values, median/IQR or confidence intervals, multi-seed variability, and paired section-level comparisons; avoid spot-level significance tests that create pseudoreplication.
- The `src/train/` projector's best canonical results select checkpoints by `similarity_gap`, while `loss` selection materially underperformed. Validate projection changes with the leave-one-out ground-truth k-NN analysis; `k=49` was selected by direct accuracy maximization, not an elbow rule.
- `sklearn` operations are CPU-only. Spectral clustering on all 47k spots is known to be very slow; do not imply that PyTorch device selection accelerates it.

## Commands And Artifacts

- Install with `pip install -e ".[dev]"`; `requirements-lock.txt` is a machine-specific reference, not the project installation input. Run modules from the repository root: `python -m src.<package>.<module>`.
- Run `pytest` or `pytest src/test/test_dlpfc_checkpoint.py::test_checkpoint_reports_all_twelve_sections`. The dataset test is skipped until `checkpoints/dlpfc.pkl` exists; create it with `DlpfcDataset.build_or_load(root=".", checkpoint_path="checkpoints/dlpfc.pkl")`.
- Use `python -u` for long jobs so redirected progress remains visible. Generated `data/`, `Dataset/`, `checkpoints/`, and almost all `outputs/` are git-ignored; only `outputs/README.md` is tracked.
